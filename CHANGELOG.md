# CHANGELOG

## 4.0.0

### Единая таблица хранения: кластеризация, dims-skip, TTL без rollup

- **Breaking: удалены форматы v1/v2 и миграция.** Сегмент пишется только в
  бинарный контейнер v4 (`JSDB` + байт версии 4, иначе `SFW3_BAD_VERSION`);
  `.json`-сегменты и `migrateToV3()` из API убраны — обратной совместимости
  со старыми каталогами нет (формат ещё не эксплуатировался).
- **Кластеризация данных (`cluster`)**: `defineLogTable`/`defineUpsertTable`
  принимают `cluster: ['met','dev']` — компакция сортирует сегменты по
  измерениям (dims → ts ↑); `Table/Journal.clusterCompact(start?, end?)` —
  перекомпоновка окна; `setCluster` меняет spec существующей таблицы
  (манифест + metadata журналов). Валидация spec — `DEF_CLUSTER_*`.
- **Новые поля `.meta`: `dims`, `cluster`, `tsOrdered`** (все выводимые —
  восстанавливаются из сегмента). `dims` — точный набор значений (≤64) или
  числовой диапазон по cluster-полям: `where` по измерению пропускает сегмент
  целиком даже без ts-фильтра (`eq/in/isNull` по set; числовые `eq/in` по range;
  `ne/nin/диапазонные` — никогда). Кластеризованный сегмент несёт
  `tsOrdered: false` — ранний стоп limit-сканов включается только когда все
  закрытые сегменты окна ts-упорядочены (корректность `scan limit` на
  кластеризованных данных).
- **Сублинейный скан по измерениям**: замеры со счётчиком загрузок сегментов
  (`test/test-cluster.ts`): `where` по редкому значению после кластеризации
  грузит долю сегментов; до — все.
- **`Table.aggregate(start, end, exprs, where?)`**: фильтр `where` проталкивается
  в каждый журнал; в тир-режиме агрегаты тиров склеиваются аккумуляторами
  (`min/max/sum/count` аддитивны, `avg` = сумма/счёт), groupBy-ключи сливаются.
  Материализация строк не используется.
- **Одно-тирной retention = чистый TTL**: одна пара `res:ttl` в `retention`
  валидна без `agg` (rollup no-op, авто-purge по TTL); при ≥2 тирах `agg`
  по-прежнему обязателен (`DEF_RETENTION_AGG`).

### Чтение и формат: pushdown, merge-чтение тиров, compact-хвосты v3

- **Зональная фильтрация сегментов:** `where` теперь отсекает сегменты целиком
  по саммари из `.meta` (`SegmentMeta.skipsWhere`) — `gt/ge/lt/le/eq/in` при
  ts-фильтре, `isNull` при полном числовом покрытии. Консервативно: саммари
  считаются только по строкам с числовым ts, поэтому без ts-фильтра skip
  запрещён; `ne/nin/isNotNull` не пропускают никогда.
- **Тир-таблица без полного материалала:** `Table.scan` в tier-режиме проталкивает
  `where`/`select`/бюджет строк (`offset+limit` при asc) в каждый journal-scan,
  а тир-списки (каждый уже отсортирован) сливаются k-way merge вместо глобальной
  сортировки всех строк.
- **v3: бинарный хвост rowMap** (u32 LE на логическую строку вместо JSON-массива,
  ~4× дешевле); контейнер с этим хвостом — **версия 4** (байт версии в заголовке),
  файлы версии 3 с JSON-rowMap читаются как раньше, различие — по байту версии.
- **v3: честный compression:** в файл пишется резолювнутый способ (zstd без
  поддержки Node → gzip), а декодирование zstd-файла без zstd даёт явную ошибку
  `SFW3_ZSTD_REQUIRED`, а не тихое падение/подмену.
- **Авто-кодек пробывает все кодеки** (несовместимые отбрасываются) и выбирает
  самый компактный; с 3.x прогон ранжируется по равномерной выборке ≤512 значений,
  победитель кодирует столбец один раз (на больших сегментах — без полного
  прогона всех кодеков по всем значениям).
- **WAL-watermark:** строки WAL нумеруются (`<seq> <json>`), закрытые сегменты
  хранят `walSeq` (в файле и `.meta`); replay пропускает покрытые seq — крах
  между записью сегмента и усечением WAL больше не даёт дублей. Обрывок
  **последней** строки WAL отбрасывается (tolerant tail), порча в середине —
  явная ошибка `JRN_WAL_CORRUPT`. Легаси `wal.log` от версий до watermark
  (строки без seq-префикса) реплеится целиком, без пропуска по watermark.
- **Rollup больше не глотает ошибки скана:** сбой на странице прерывает rollup
  до движения чекпоинта (прежде битые данные становились «прожатыми» молча).

### WAL настраиваемый — `wal: 'on' | 'off'` (дефолт изменён!)

- **Breaking-дефолт:** WAL теперь **выключен** (`wal: 'off'`): append не
  пишет `wal.log` вообще — вдвое меньше записанных байтов и износа SSD. Цена:
  при гибели процесса строки активного сегмента теряются. Прежнее поведение —
  `{ wal: 'on' }` (уровень: `Journal`, `Store`, override на журнал в
  `openJournal`; через define* — в `opts`).
- `wal: 'off'`: нет `wal.log`, нет строковой сериализации в writer'е; чистое
  `close()`/flush работают без изменений. `wal: 'on'` — прежнее поведение плюс
  watermark (см. выше): `JRN_OPT_WAL` на невалидное значение.
- Тесты: `test-durability` — новый сценарий off-краха (строки теряются,
  `wal.log` не создаётся); WAL-сценарии явно включают `wal: 'on'`.

### Дешёвые оптимизации: корректность раннего стопа + `.meta` для статистик

- **Фикс раннего стопа скана:** раньше `limit`-скан останавливался при
  сортировке не по ts (top-k по выбранному полю давал не те строки), без
  ts-окна (строки без ts ломали порядок) и при сегментах без `.meta` (такой
  сегмент уезжает в конец `sortedIds()` независимо от реальных ts). Теперь
  ранний стоп только при `sortKey = ts` + ts-окне + числовых `.meta`-границах
  у всех закрытых сегментов; иначе — полный скан с сортировкой (как было всегда
  семантически, просто медленнее).
- **`.meta` дешевле:** сайдкар пишется одним `write` вместо tmp+rename (это
  выводимые данные — `loadClosed()` восстанавливает их из сегмента), минус
  лишняя запись на каждый сегмент; в `.meta` добавлен `bytes` (размер файла
  сегмента) — `info()`/статистике больше не нужен `stat` по каждому файлу.
- **Статистика таблиц без разжатия:** `Store.describe()` берёт `rowCount` из
  `.meta`; сам сегмент декодируется только если сайдкара нет/он битый.
- Тесты: `test-scan` — 3 регресса раннего стопа (сегмент без `.meta`,
  сортировка по не-ts полю, строки без ts); `test-table` — `bytes` в `.meta`
  и `describe()` по битому сегменту.

### Фиксы по итогам ревью

- **CRITICAL легаси-WAL:** leftover `wal.log` версий до watermark (строки без
  seq-префикса) больше не считается порчей — такие строки реплеятся целиком,
  без пропуска по watermark.
- **Валидация seq-префикса:** `seq` обязан быть целым безопасным числом и строго
  расти; нарушение в любой позиции WAL — `JRN_WAL_CORRUPT` (логическая порча,
  tolerant-обход применяется только к непарсящемуся JSON последней строки).
- **Неатомарная `.meta` vs watermark:** если у закрытого сегмента `.meta` утрачен
  (запись сайдкара прервалась), перед replay метаданные достраиваются из самих
  сегментов — заниженный `maxWalSeq` больше не даёт дубли строк
  (`SegmentStore.repairMissingMeta()`).
- **Ранний стоп top-k — полный гейт:** к прежним условиям добавлены
  неперекрывающиеся диапазоны закрытых сегментов (строгий `prev.maxTs < next.minTs`)
  и полный ts-покрытость всех источников (`tsCount === rowCount`); top-k без
  ts-окна снова разрешён, когда строк без ts нет вовсе. Ранний стоп подразумевает
  неубывающий порядок append'ов по ts (инвариант журнала) — см. `docs/Querying.md`.
- **v3-контейнер — версия 4:** формат контейнера изменён (бинарный rowMap-хвост),
  но байт версии не был поднят; теперь записывается 4, читатель принимает 3 и 4,
  а v4 без `rowMapLen` в шапке — явная ошибка `SFW3_NO_ROWMAP`. Хардкоды версии
  в retention-инспекции и детекте формата исправлены.
- **Codec-probe по выборке** (≤512 равномерных значений) вместо полного прогона
  всех кодеков по всему столбцу; победитель кодирует столбец один раз.
- **`SegmentMeta.fromSegment()`** — единая фабрика меты вместо двух дублирующих
  литералов в `SegmentStore`.
- Тесты: `test-durability` — легаси-WAL, битый/немонотонный seq, рваный `.meta`
  при непустом WAL (без дублей); `test-scan` — перекрывающиеся диапазоны и
  top-k без окна при полном ts-покрытии; `test-v3-format` — версия 4, чтение
  легаси v3, `SFW3_NO_ROWMAP`, совпадение победителя sampled-probe с полным
  прогоном.

## 3.1.1

### Rollup без OOM — пагинация + инкрементальный аккумулятор

- **Второй OOM-вектор на hot path:** `rollup()`/`rollupOne()` делали
  `fine.scan(окно)` (весь rollable-окно тонкого тира в один массив) +
  `Rollup.promote`, который внутри собирал **полные массивы значений** на
  каждую группу. При отстающем rollup окно разрастается → пик кучи в разы
  больше данных → тот же `Ineffective mark-compacts` → OOM.
- **Фикс:** fine-тир читается **страницами по времени** (ширина страницы =
  целевое разрешение тира), а агрегация — инкрементально. Пик памяти теперь
  ограничен числом бакетов, а не числом строк тонкого тира.
- **Новый публичный API:** `Rollup.accumulate(cfg)` →
  `{ add(row), finalize() }` — бегущий `{count,sum,min,max}` на поле
  (O(1) на группу вместо массива значений). Покрывает все пять аггов
  (avg = sum/count). `Rollup.promote()` остаётся как тонкая обёртка — API и
  семантика (порядок групп, null-поля) не изменились.
- Окно пагинации `(пред, конец]` по инклюзивным границам `scan()` — строки
  не дублируются и не теряются; результат идентичен прежнему single-scan.
- Чекпоинт и purge — без изменений (идемпотентность rollup сохранена).

## 3.1.0

### Авто-компакция под нагрузкой — без OOM

- **Причина OOM под высокой нагрузкой:** при заполнении `rowsPerSegment`
  `append()` синхронно вызывал `compact()`, который грузил **всю** таблицу в
  память за один раз (`rows[]` + `kept[]` + перекодированный `merged`). На
  большом объёме это пик кучи в разы больше таблицы → GC-шторм
  (`Scavenge during sweeping` / `Mark-Compact reduce`) →
  `Ineffective mark-compacts near heap limit` → зацикливание append → compact → OOM.
- **Фикс:** `append()` больше не делает синхронный full-merge. Он запускает
  **один bounded-пасс** — сливает ≤ `_compactRowsPerPass` строк (по умолчанию
  200k), а остаток долга самочинится фоновыми шагами через `setImmediate`, не
  блокируя запись. Куча никогда не держит всю таблицу одновременно.
- **Самонастройка под нагрузку:** размер пасса адаптивно подстраивается —
  медленный шаг уменьшает батчи (легче под нагрузкой), быстрый — увеличивает
  (меньше смен). Диапазон 20k–500k строк, целевое время шага 25 мс.
- Явный `compact()` сохраняет прежний синхронный full-merge (и миграцию
  v2→v3 одиночного сегмента); автоматический путь — только bounded-пассы.
- Публичное API не меняется; поведение под нагрузкой — теперь без heap-пика.

## 2.5.0

### Единый менеджер ошибок (`ErrorManager`)

- Все броски в `src` переведены с «голых» `RangeError`/`TypeError`/`Error` на
  **кодированные ошибки** через `ErrorManager`. Каждая ошибка несёт стабильный
  код (`e.code`) — программная обработка по коду, а не по тексту или типу.
- Коды сгруппированы по компонентам: `JRN_*` (Journal/Interval), `TBL_*`
  (Table), `SQL_*` (Sql). Формат сообщения: `КОД: описание [ключ=значение …]` —
  данные не интерполируются в текст, а приписываются в скобках.
- Публичные хелперы для вызывающего слоя: `ErrorManager.isError(e)` (это ли это
  наша ошибка), `ErrorManager.isCode(e, 'JRN_LOCKED')` (конкретный код),
  `ErrorManager.get(short)` (определение кода).
- Удалён отдельный класс `SqlError.ts` — его коды перенесены в `SQL_*`.
- API бросков внутри `src` не меняется для потребителя: ошибки по-прежнему
  бросаются в тех же местах, только теперь с `code`.

## 2.4.0

### Экспорт `Interval`

- `index.ts` экспортирует **Interval** — публичный парсер времени: `period(start, end)`,
  интервалы вида `15m`/`1h`/`1d`. Позволяет вызывающему слою самостоятельно резолвить
  относительные периоды (`'now-6h'` → мс), не дублируя логику DB.

## 2.3.0

### `Table.truncate()` — полная очистка таблицы

- `table.truncate()` → `{ removedRows }`: удаляет **все** строки из памяти и с
  диска — сегменты, `.meta`, WAL, остатки `.tmp` во всех тирах. В отличие от
  `purge(until)`, исключений нет: удаляются и строки без `ts`, и свежие.
- Rollup-чекпоинты сбрасываются (в тир-режиме удаляется и `_rollup.json`) —
  иначе условие `maxRollable <= cp` навсегда блокировало бы перенос новых
  строк с `ts` ниже прежнего максимума.
- Таблица остаётся открытой: сразу можно продолжать `append()` — это чистая
  таблица с прежней схемой. Персистентно: после reopen данные не возвращаются.
- Экспортирован новый публичный тип `TruncateResult`.
- Тесты: 13 проверок (одиночный режим, строка без `ts`, персистентность после
  reopen, тир-режим со сбросом чекпоинта и повторным rollup).

## 2.2.0

### Публичный API — одно лицо (ClickHouse-модель)

- `index.ts` экспортирует только **Store**, **Table**, `define*Table` и
  публичные типы. Внутренняя механика (Journal, Segment, кодексы, SQL-парсер)
  больше не является публичным API (RULES.md §5).
- **Store** — каталог таблиц: `create(def)`, `open(name)`, `describe()`,
  `tables()`, `engineOf(name)`, `stats()`, `closeAll()`; общий кэш сегментов;
  манифест `_store.json` (самодостаточный артефакт: движок + схема + тиры).
- **Описания таблиц** — `defineLogTable`, `defineUpsertTable`,
  `defineSummingTable`, `defineCollapsingTable`: валидация при объявлении,
  не при первом compact().

### Движки слияния

- `log` — строки не меняются, дубли схлопываются;
- `upsert` — по `key` остаётся строка с max(`version`);
- `summing` — по `key` суммируются колонки из `sum`;
- `collapsing` — по `key` гаснут пары +1/−1 в колонке `sign`.

### CLI `vrack2-journal`

`create`, `append`, `query`, `stats`, `compact`, `tables` — записывать/смотреть
метрики из shell. `--ts` в мс (значения < 1e12 — секунды), `--from/--to` —
число или `'now-1d'`.

### Надёжность

- Отклонённый append (нарушение схемы) больше не портит WAL: запись WAL
  откатывается (буфер или уже на диске), следующая `open()` не падает.
  Регресс-тест в `test-durability.ts` (сценарий 6).

### Тесты

- 19 сценариев, 1094 проверки; `npm test`, `npm run typecheck`, `npm run build`.
