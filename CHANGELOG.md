# CHANGELOG

## 3.0.0

### Удалён SQL-lite (breaking)

- Удалён `src/Sql.ts` (класс `Sql`, `Sql.parse()`, `Sql.parseInsert()`,
  `InsertQuery`, токенизатор/парсер) и все коды ошибок `SQL_*`.
- Удалены методы `Journal.sql()` и `Table.sql()` вместе с кодами ошибок
  `JRN_INSERT_NAME`, `JRN_FROM_NAME`, `TBL_INSERT_NAME`, `TBL_TABLE_NAME`,
  `TBL_GROUP_BY_TIER`, `TBL_WHERE_AGG_TIER`.
- Удалено поле `ScanOptions.table` (использовалось только SQL-путём).
- Удалён `test/test-sql.ts` и его вызов из скрипта `test`.
- Функционал SQL покрывается обычным API: `SELECT` → `scan()`, агрегации →
  `aggregate()`, `INSERT` → `append()`.

## 2.5.0

### Единый менеджер ошибок (`ErrorManager`)

- Все броски в `src` переведены с «голых» `RangeError`/`TypeError`/`Error` на
  **кодированные ошибки** через `ErrorManager`. Каждая ошибка несёт стабильный
  код (`e.code`) — программная обработка по коду, а не по тексту или типу.
- Коды сгруппированы по компонентам: `JRN_*` (Journal/Interval), `TBL_*`
  (Table), `SQL_*` (Sql). Формат сообщения: `КОД: описание [ключ=значение …]` —
  данные не интерполируются в текст, а приписываются в скобках.
- Публичные хелперы для вызывающего слоя: `ErrorManager.isError(e)` (это ли это
  наша ошибка), `ErrorManager.isCode(e, 'JRN_LOCKED')` (конкретный код),
  `ErrorManager.get(short)` (определение кода).
- Удалён отдельный класс `SqlError.ts` — его коды перенесены в `SQL_*`.
- API бросков внутри `src` не меняется для потребителя: ошибки по-прежнему
  бросаются в тех же местах, только теперь с `code`.

## 2.4.0

### Экспорт `Interval`

- `index.ts` экспортирует **Interval** — публичный парсер времени: `period(start, end)`,
  интервалы вида `15m`/`1h`/`1d`. Позволяет вызывающему слою самостоятельно резолвить
  относительные периоды (`'now-6h'` → мс), не дублируя логику DB.

## 2.3.0

### `Table.truncate()` — полная очистка таблицы

- `table.truncate()` → `{ removedRows }`: удаляет **все** строки из памяти и с
  диска — сегменты, `.meta`, WAL, остатки `.tmp` во всех тирах. В отличие от
  `purge(until)`, исключений нет: удаляются и строки без `ts`, и свежие.
- Rollup-чекпоинты сбрасываются (в тир-режиме удаляется и `_rollup.json`) —
  иначе условие `maxRollable <= cp` навсегда блокировало бы перенос новых
  строк с `ts` ниже прежнего максимума.
- Таблица остаётся открытой: сразу можно продолжать `append()` — это чистая
  таблица с прежней схемой. Персистентно: после reopen данные не возвращаются.
- Экспортирован новый публичный тип `TruncateResult`.
- Тесты: 13 проверок (одиночный режим, строка без `ts`, персистентность после
  reopen, тир-режим со сбросом чекпоинта и повторным rollup).

## 2.2.0

### Публичный API — одно лицо (ClickHouse-модель)

- `index.ts` экспортирует только **Store**, **Table**, `define*Table` и
  публичные типы. Внутренняя механика (Journal, Segment, кодексы, SQL-парсер)
  больше не является публичным API (RULES.md §5).
- **Store** — каталог таблиц: `create(def)`, `open(name)`, `describe()`,
  `tables()`, `engineOf(name)`, `stats()`, `closeAll()`; общий кэш сегментов;
  манифест `_store.json` (самодостаточный артефакт: движок + схема + тиры).
- **Описания таблиц** — `defineLogTable`, `defineUpsertTable`,
  `defineSummingTable`, `defineCollapsingTable`: валидация при объявлении,
  не при первом compact().

### Движки слияния

- `log` — строки не меняются, дубли схлопываются;
- `upsert` — по `key` остаётся строка с max(`version`);
- `summing` — по `key` суммируются колонки из `sum`;
- `collapsing` — по `key` гаснут пары +1/−1 в колонке `sign`.

### CLI `vrack2-journal`

`create`, `append`, `query`, `stats`, `compact`, `tables` — записывать/смотреть
метрики из shell. `--ts` в мс (значения < 1e12 — секунды), `--from/--to` —
число или `'now-1d'`.

### Надёжность

- Отклонённый append (нарушение схемы) больше не портит WAL: запись WAL
  откатывается (буфер или уже на диске), следующая `open()` не падает.
  Регресс-тест в `test-durability.ts` (сценарий 6).
