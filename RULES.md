# RULES.md — Правила структуры и именования кода

## 1. Группировка по сущности

Каждый файл представляет **одну** когерентную сущность: класс, набор тесно связанных утилит, или набор типов.

**Проблема, которую решаем:**
Пачка `export function` в одном файле не даёт ответа на вопросы:
- кому принадлежит функция?
- кто её может использовать?
- что приватное, а что публичное?

**Правило:**
Если функции оперируют одними и теми же данными / концепцией — они принадлежат **одному классу** (или статическому классу).
Если функции реально независимы — они живут в разных файлах.

```
❌  codec.ts:  export function encodeSegment()
             export function decodeSegment()
             export function isCompressedFormat()
             function _decodeV2()
             function _msg()

✅  SegmentFile.ts:  class SegmentFile {
                       static encode(data): Buffer
                       static decode(buf): SerializedSegment
                       static isV2(buf): boolean
                       # decodeV2(buf)
                       # msg(e)
                     }
```

**Критерий:** если у тебя в голове есть слово-сущность («сегмент», «кодек», «движок», «тир»), то функции вокруг этой сущности — методы/статические методы класса с этим именем.

---

## 2. Именование файлов

| Что в файле | Имя файла | Пример |
|---|---|---|
| Класс (главная сущность) | **PascalCase** = имя класса | `MergeTree.ts`, `Tier.ts`, `Log.ts` |
| Функции одной сущности (статический класс) | **PascalCase** = имя сущности | `SegmentFile.ts` |
| Набор независимых утилит / хелперов | lowercase | `define.ts`, `rollup.ts` |
| Только типы | lowercase | `types.ts` |
| Фасад / реэкспорт | `index.ts` | `index.ts` |

**Запрещено:** camelCase для файла, содержащего класс (`mergeTree.ts` с классом `MergeTree` — ошибка).

---

## 3. Приватность

- Приватные функции **внутри класса** → `private` или `#`-префикс.
- Приватные функции **внутри модуля** (без класса) → `_`-префикс ИЛИ `// @internal` комментарий.
- Публичный API файла = **только** то, что экспортируется. Всё, что не экспортировано, — приватное.

**Запрещено:** `export function _internalThing()` — если оно не часть API, не экспортируй.

---

## 4. Разделение по домену (каталоги)

Каталог = доменная зона. Внутри каталога — файлы по сущностям.

```
src/
├─ compaction/       ← как сжимать данные при compact()
├─ metricTable/      ← мультитирная метрика-таблица
├─ ...
```

**Запрещено:** каталог `engines/` (слишком общее), в котором живут и движки сжатия, и метрики, и утилиты. Если название каталога не описывает **одну** зону ответственности — переименуй или расколи.

---

## 5. Публичный API

- Публичный API модуля определяется **только** `export`.
- Не экспортируй реестры/синглтоны (`engines`, `logEngine`) — это скрытая зависимость. Клиент должен создавать экземпляр: `new Upsert(descriptor)`.
- Не экспортируй вспомогательные типы, которые нужны только внутри (оставь их локальными).
- `index.ts` (фасад) — единственный файл, который собирает публичный API пакета. Всё остальное — внутреннее.

---

## 6. Один файл = одна ответственность

Файл содержит **либо** класс, **либо** набор функций одной сущности, **либо** типы.

**Запрещено:**
- Файл, где 50% — класс, а 50% — свободные функции, не относящиеся к классу.
- Файл, где две разные сущности (`Tier` + `Rollup`) без причины лежат в одном файле.

Если видишь разделительный комментарий `// ===== Entity A =====` и `// ===== Entity B =====` в одном файле — это сигнал, что это **два файла**.

---

## 7. Конструктор и данные

- Если сущность хранит состояние — это **класс с конструктором**, а не набор функций, принимающих `ctx`/`config` как первый аргумент.
- Если сущность **не** хранит состояние (чистые преобразования) — статический класс или свободные функции допустимы.

```
❌  function merge(rows, ctx, engine, keyFields) { ... }
    function merge(rows, ctx, engine, keyFields) { ... }  // другой файл

✅  class Upsert extends Engine {
       merge(rows): Row[] { ... }
     }
```

---

## 8. Переименование и согласованность

- Имя класса и имя файла **совпадают** (PascalCase).
- Имена методов отражают действие, а не внутреннюю реализацию.
- Если функция называется `applyAgg` — это неясно, ЧТО агрегируется. Лучше `aggregateForTier`.
- Магические константы именованы `UPPER_SNAKE_CASE` и живут рядом с их использованием (в классе или в начале файла), а не размазаны.

---

## 9. Зависимости

- Зависимость должна идти «вниз»: верхний уровень знает о нижнем, но не наоборот.
- `journal.ts` → `compaction/` ✓
- `compaction/` → `journal.ts` ✗ (цикл)
- Если два файла друг друга импортируют — это сигнал, что они **одна** сущность и должны быть в одном классе/файле.

---

## 10. Проверка

Перед тем как считать задачу завершённой:
1. `tsc --noEmit` — без ошибок.
2. `npm test` — все тесты зелёные.
3. Пройдись глазами по каждому файлу: **могу ли я за 3 секунды сказать, кто владелец каждой export-функции?** Если нет — группировка не завершена.
