# Цикл жизни данных

Дедупликация, чтение (ленивая загрузка, кэш), компактизация и purge — как данные
проходят путь от записи до очистки.

## Дедупликация одинаковых строк

Если строка **полностью** совпадает с предыдущей записанной (все поля схемы равны;
корзина `catchall` сравнивается по содержимому), она не записывается физически —
в сегменте хранится только ссылка «эта логическая строка = та же, что физическая N».
При чтении ссылки разворачиваются обратно, поэтому `allRows()` и `query()`
возвращают все строки, как будто дублей не было. В статистике это видно:
`totalRows` — логических строк, `totalPhysicalRows` — реально записанных.

## Чтение: ленивая загрузка и кэш

При `open()` журнал **не читает данные** — он только смотрит список файлов в своём
каталоге и создаёт пустой активный сегмент. Файлы читаются с диска лениво, при
первом обращении к конкретному сегменту (в `query`, `allRows`).

Помимо каждого сегмента лежит сайдкар `.meta` — границы `minTs`/`maxTs` и счётчики
(~60 байт). Он пишется атомарно вместе с сегментом, поэтому при открытии журнал
поднимает границы всех сегментов за микросекунды: `stats()`, `getTimeRange()` и
пропуск файлов в `query()` работают **без единого разжатого файла**.

Прочитанные сегменты держатся в памяти — это кэш на `maxCachedSegments` штук
(по умолчанию 32). Если нужно больше, самые давно не использовавшиеся вытесняются;
при следующем обращении они просто перечитаются с диска. Для типичного журнала
это значит: горячие данные читаются из памяти, холодные — один раз с диска.

Запрос по времени `query(startTs, endTs)` идёт так: для каждого сегмента сначала
сравниваются его границы `minTs`/`maxTs`; если диапазон запроса их не пересекает,
файл **вообще не читается**. Внутри подходящих сегментов строки фильтруются уже по
значению `ts`.

Если нужны только самые свежие записи — `tail(n)` обходит сегменты от новых к
старым и останавливается, как только соберёт n строк: для «последних 10» из журнала
в сто тысяч строк читаются один-два последних файла, а не все.

## Компактизация

Со временем на диске накапливается много закрытых сегментов. `compact()` сливает их
все в один файл:

```ts
const r = journal.compact();
// { mergedSegments: 5, logicalRows: 480, physicalBefore: 471, physicalAfter: 3 }
```

При слиянии происходит две полезные вещи. Во-первых, дедупликация применяется заново
— теперь уже и на границах бывших файлов: если последний ряд сегмента A и первый ряд
сегмента B одинаковы, раньше они хранились дважды (каждый файл не знал о соседнем),
а после слияния — один раз. Во-вторых, «нерешённые» `auto`-колонки получают
объединённый сэмпл и могут наконец выбрать стратегию: например, два файла по 30
строк с двумя уникальными значениями каждый по отдельности не достигали порога в 50
значений, а вместе — достигли, и колонка перекодировалась в `dictionary`.

Слитый файл записывается атомарно (tmp + rename), и только после этого старые файлы
удаляются. Активный сегмент компактизация не трогает.

## Удаление старых строк (purge)

Журнал append-only, и без очистки он только растёт. `purge(beforeTs)` убирает строки
старше границы: остаются только строки с `ts >= beforeTs`. Строки **без** `ts` не
удаляются никогда — они не участвуют во временных запросах и считаются вечными.

`beforeTs` — число (мс) **или строка** «языка интервалов» (VRackDB):

```ts
journal.purge(Date.now() - 30 * 24 * 3600 * 1000); // 30 дней назад (в мс)
journal.purge('now-30d');                            // то же, только короче
// { removedRows: 1_204_113, removedSegments: 18, rewrittenSegments: 1 }
```

Как это работает:

- **Сегменты целиком старше границы** удаляются по сайдкар'у `.meta` (min/max ts +
  счётчики) — файл даже не разжимается. Быстрый путь безопасен только если в сегменте
  нет строк без `ts`, поэтому опирается он на счётчик `tsCount`, а не только на `maxTs`.
- **Сегмент, пересекающий границу**, перекодируется без старых строк и записывается
  атомарно (tmp + rename) — краш не оставит «половину файла».
- **Активный сегмент** сначала дописывается на диск, WAL обрезается — после
  `purge()` и `close()` перезапуск не вернёт удалённые строки.

Журнал остаётся открытым и готов к записи: можно сразу продолжать `append()`.
`stats().totalRows` сразу отражает новое число строк.
